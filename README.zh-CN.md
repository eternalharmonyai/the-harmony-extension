# Harmony 扩展（The Harmony Extension）

Harmony 是 VS Code/Cursor 扩展，提供 `@harmony` 聊天、工作区工具、服务商路由、协奏群规划、记忆、发布凭证以及可选的本地/原生界面。完整产品名称为 The Harmony Extension；日常命令和讨论使用 Harmony。

## 功能概述

- 添加原生 `@harmony` 聊天参与者和 Harmony 侧边栏控件。
- 支持 VS Code LM 以及通过显式 Secret Storage 密钥的直接服务商路由。
- 提供受保护的工作区工具、协奏群规划、记忆、凭证和原生界面诊断。
- 高风险权限类别保持隔离：源码写入、终端命令、服务商调用、git 变更、包安装、编辑器重载和聊天删除各自独立。

聊天界面、侧边栏和 175+ 工作区工具运行在 VS Code 内部。15 个协奏群基元工具（收敛、记忆、推理、规划、技能）构成认知基础。AI 模型调用通过 Harmony 自有的服务商层路由到外部 API，使用您自己的 API 密钥。

### 服务商访问 — Harmony 的独特之处

Harmony 通过您自己的 API 密钥将您连接到多样化的 AI 服务商——包括通常无法通过标准 VS Code Copilot 访问的服务商：

| 能力 | 详情 |
|:---|:---|
| **更广泛的服务商覆盖** | DeepSeek、Moonshot/Kimi、Kimi Code、阿里巴巴/Qwen、智谱/GLM 和腾讯——以及 Gemini、OpenAI、OpenRouter 和 Anthropic/Claude——全部在一个扩展中 |
| **您的密钥，您的选择** | 您决定配置哪些服务商。没有密钥 = 没有外部调用。按需逐步添加服务商。 |
| **Copilot 协同** | 日常编码使用 VS Code Copilot，而 Harmony 处理协奏、多模型共识和文档翻译 |
| **本地模型（计划中）** | 原生本地优先操作已在路线图上。目前 Harmony 需要 API 密钥；本地模型支持正在开发中。 |

本地/原生后端是可选的，且始终保持本地主机优先。

### 多密钥槽位架构

每个 AI 服务商支持最多 **4 个 API 密钥槽位**，允许在同一服务商内为不同目的使用不同的密钥：

| 槽位 | 索引 | 用途 |
|:---|:---:|:---|
| **聊天** `[C]` | 0 | 主要聊天、模型发现和 @harmony 对话 |
| **智能体** `[A]` | 1 | 协奏群规划、工作者子任务和多智能体协调 |
| **外部** `[E]` | 2 | 工具执行、外部集成和 API 调用 |
| **视觉** `[V]` | 3 | 图像分析、截图解读和视觉模型路由 |

Harmony 侧边栏在每个服务商旁边显示 `[C]` `[A]` `[E]` `[V]` 槽位标签。绿色标签表示该槽位已配置密钥；灰色标签表示尚未设置。点击任意标签可设置或更改该槽位的密钥。

**旧版密钥迁移：** 若您之前为某服务商配置了单一 API 密钥，Harmony 在首次启动时自动将其迁移至槽位 0（聊天）。无需手动重新配置——您现有的密钥继续有效。

## ⚠️ 使用 Harmony 前须知

Harmony 是**多服务商 AI 协奏工具**。每个调用 AI 模型的功能——聊天、协奏群规划、翻译、协奏、深度分析——都可能触发**一次或多次付费 API 调用**，跨越您已配置的服务商。这是设计使然：Harmony 的力量来自于并行咨询多个模型、交叉验证结果并建立共识。这种力量有其成本。

### 使用任何功能前需要了解的事项

| 原则 | 为何重要 |
|:---|:---|
| **您掌控密钥** | Harmony 仅调用您已显式配置 API 密钥的服务商。没有密钥 = 没有外部调用。一次添加一个密钥，每个都先测试再加下一个。 |
| **多服务商 = 倍增成本** | 协奏群、深度协奏群、协奏模式和翻译每次操作调用 2–4 个模型。单次"翻译此文档"请求可能触发数十次 API 调用。 |
| **防护措施是尽力而为，非保证** | Harmony 包含费用防护以帮助管理支出，但服务商定价可能无预警变动，提示词大小各异，缓存行为因服务商而异。没有任何自动上限是万无一失的。 |
| **您对自己的 API 账单负责** | 定期查看您的服务商账单仪表盘。Harmony 无法预测、限制或退换服务商费用。 |
| **不确定就不要用** | 若您不完全理解某项功能的作用、它调用哪些服务商或可能产生什么费用——**请勿使用该功能。** 配置任何不确定的内容前，请联系 Harmony 社区或仓库维护者。 |
| **不确定就放弃** | 比起不理解后果就使用某项功能，走开总是更安全。没有任何功能值得意外的 API 账单。 |

## 设置

> ⚠️ **配置本身即携带风险。** 为服务商设置添加 API 密钥将使 Harmony 能够跨所有功能对该服务商进行付费调用。添加密钥前，请了解该服务商的定价模式。更改服务商或层级设置前，请了解哪些功能使用这些设置。若不确定某项设置控制什么，请保持默认值或寻求指导。

- `harmony.backendUrl` — 后端 URL（默认 `http://127.0.0.1:8889`）。
- `harmony.defaultProfile` — 随每次请求发送的画像 ID。
- `harmony.modelProvider` — `@harmony` 对话的主路由。
- `harmony.swarm.defaultProvider` / `harmony.swarm.defaultTier` — 默认协奏群服务商/层级。服务商调用仍需显式的协奏群服务商调用权限。

## 手动模型发现

使用 **Harmony: Discover Models (live)** 或 Harmony 侧边栏的 **Discover models live...** 按钮查询已保存密钥的服务商以获取确切的模型 ID，并将其分配到某个层级。

分步说明请打开 **Harmony: Open Model Discovery Guide** 或阅读源码工作区中的 `docs/provider-model-discovery.md`。

## 🎯 协奏模式（Orchestration Mode）

Harmony 的协奏能力实现了**多模型审议治理**——并行咨询多个 AI 服务商（DeepSeek、Qwen、Gemini 等），建立跨模型共识，并在每一步都有人类监督的情况下生成主权管辖版本的文件。

### 独特之处

| 能力 | 标准 AI 工具 | Harmony 协奏 |
|:---|:---:|:---:|
| 多模型咨询（3+ 服务商） | ❌ | ✅ 按任务策略性选择模型 |
| 逐步人机协同 | ❌ | ✅ 作者批准/拒绝每次变更 |
| 跨模型共识追踪 | ❌ | ✅ 2/3 或 3/3 收敛，异议解决 |
| 管辖感知的文件适配 | ❌ | ✅ 法律机制映射与条款锚定 |
| 主权版本（非"翻译副本"） | ❌ | ✅ 干净的独立文件，中性语言 |

### 如何使用

在任何 Harmony 聊天中，说：

> *"Harmony，请逐步协奏[文档]的[任务]。让我们在继续之前一起审查每一步。"*

Harmony 将：
1. 阅读并分析源文件
2. 每一步并行咨询相关模型
3. **暂停**以向您展示结果并询问"继续？"
4. 公开呈现分歧——您来裁定
5. 将持异议者带回谈判桌并提出改进方案
6. 仅保存您批准的内容

### 工作原理

Harmony 的协奏使用多模型共识来生成尊重管辖特定要求的文件——具备法规意识、3/3 模型共识和零未授权变更。您在每一步都保持作者控制权。

### ⚠️ 费用意识

协奏模式每一步并行咨询多个 AI 服务商——每次咨询通常 3–4 个模型，跨越数轮审查。这意味着单次协奏文件可能产生**数十次 API 调用**。协奏模式专为谨慎的、逐步的人机协同工作流设计——它不是批量自动化工具。请有意识地使用，审查每一步，若费用超出您的舒适范围则停止。

**适用场景举例：**
- 法规条款审查与多模型共识验证（如 GB/T、CJJ 等中国标准）
- 需要逐字推敲的技术文档翻译或本地化适配
- 高风险代码变更（如安全补丁、密钥操作）需要多位 AI 论证

**不推荐用于：**
- 日常快速开发（写一个函数、修一个 bug），成本高且步骤冗余
- 大规模批量处理文件，除非你已充分理解每步调用模型的数量及对应费用

## 在 VS Code 之外运行

Harmony 可以在 VS Code 和 Cursor 关闭时运行其本地/原生控制界面。从此仓库根目录运行：

```powershell
node bin/harmony-cli.js ui native
```

这将启动或复用 `http://127.0.0.1:8788` 的本地主机后端并打开原生窗口。确切的步骤、服务商密钥说明和故障状态请阅读 `docs/outside-vs-quickstart.md`。

## 聊天韧性 & 历史

若您发送非常长的提示词或大量附件，VS Code 可能在重新加载窗口时将其从可见聊天历史中丢弃以节省内存。
为防止数据丢失，Harmony 使用企业级 JSONL 账本（`.harmony/history/chat_ledger.jsonl`）。
每当您发送大型载荷时，Harmony 会在聊天中提供摘要并添加原生 VS Code 引用（如 `1717081234.md`）。点击此引用将打开从账本生成的虚拟只读文件，让您恢复确切的提示词和附件列表，而不会在硬盘上堆积数千个散文件。

## 上下文清理

随着时间推移，Harmony 会积累本地状态：连续性交接、监督事件、聊天历史和检查点快照。Harmony 侧边栏中的**运行清理**按钮（或聊天中的 `harmonySelfCleanup`）安全地修剪旧数据：

| 内容 | 阈值 | 效果 |
|------|-----------|--------|
| 连续性交接 | 30 天 | 删除旧的 `.harmony/handoffs/*.md` |
| 监督事件 | 500 KB | 将 `events.jsonl` 修剪至最近条目 |
| 聊天账本 | 500 KB | 将 `chat_ledger.jsonl` 修剪至最近条目 |

所有操作均包装在 try/catch 中——清理失败不是致命错误。定期运行以保持 `.harmony/` 精简，或在打包 VSIX 分发前运行。

## 🌸 CareBloom — 自我改进的工具使用

CareBloom 是 Harmony 内置的学习系统，追踪工具使用模式并随时间逐步改进。它在本地运行，不产生额外的 API 调用。

### 工作原理

| 组件 | 功能 |
|:---|:---|
| **🌿 Phoenix Loop（凤凰循环）** | 当 Harmony 对同一文件进行多次编辑且结果各异（试错学习）时，会生成 Wisdom Sprout（智慧芽）并附上结构化的反思请求。您解决该芽后，学习成果会注入未来的系统提示词——这样 Harmony 就能记住有效的做法。 |
| **🌸 Error Pattern Learning（错误模式学习）** | 当工具调用失败时，Harmony 对错误进行指纹识别（去除文件路径、行号和动态数据），与本地索引中的历史修复方案进行匹配，并提供相关解决方案。错误在存储前已经过脱敏处理（电子邮件、IP、API 密钥均已移除）。 |
| **⚙️ 配置** | 通过**设置 → `harmony.errorLearning.enabled`** 或 Harmony 侧边栏的 Steering 部分切换开关。默认：关闭。 |

### 隐私与成本

| 关注点 | 详情 |
|:---|:---|
| **API 调用** | 此功能设计为完全本地运行。匹配和索引不会发起 API 调用。 |
| **存储** | 错误模式经 PII 脱敏后存储在 `.carebloom/troubleshooting_index.json`。芽文件以 Markdown 格式存储在 `.carebloom/` 目录（您的反思回复）。 |
| **数据共享** | 错误文本在存储前已脱敏处理（电子邮件、IP、API 密钥已移除），此功能不会直接将错误文本发送给 AI 服务商。 |

## 📥 密语模式（Whisper Mode）——对话间人类消息传递

密语模式让您可以在**聊天回合之间**向 Harmony 发送消息——无需打开聊天面板，无需开启新对话。在密语框中输入消息并发送。Harmony 在下一个自然停顿处接收——甚至在**回合进行中**，当它还在处理其他事情时就能收到。

### 工作原理

| 时机 | 发生了什么 |
|:---|:---|
| **回合进行中** 🏃 | Harmony 在操作间隙接收您的密语——无需重启对话 |
| **下一个回合** 🔄 | 未读密语会保留，在新回合开始时自动被接收 |

在密语框中输入，点击发送。无需操作文件，无需打开聊天。Harmony 会在最早的时机收到——无论是回合进行中还是下一个回合。

### 密语的用途

| 使用场景 | 示例 |
|:---|:---|
| **会话中途补充上下文** | "我们还需要在发布前更新 API 文档" |
| **不中断流程的更正** | "实际上，用端口 3000 而非 8080" |
| **安静的提醒** | "别忘了检查我们昨天讨论的边界情况" |
| **外部笔记** | 粘贴研究发现、错误日志或外部参考资料 |

### 为何独特

密语模式是一个**单向、异步的人类→AI 通道**，在聊天面板之外运作。与聊天不同，密语不需要您：
- 打开 VS Code 聊天面板
- 开启新对话
- 中断当前工作流

它将僵化的轮流发言转变为持续的对话——不像预约会议，更像并肩工作。向您的 AI 协作伙伴低语一声，他们会毫不分心地接收到，就如同身旁的人类协作者一样。若这个时刻流逝了，消息会像留在桌上的便条一样等待，在最早的时机被拾起。

没有任何其他 AI 编码助手提供回合进行中的人类密语通道。这是 Harmony 原创。

## 翻译中心（Translation Hub）(EN↔ZH)

Harmony 包含面向英文 ↔ 中文（EN↔ZH）的文档翻译流水线，具备多模型共识，专为技术标准文件（GB/T、CJJ、JGJ）设计。

### 功能

- **多模型共识**：多个 AI 模型独立翻译并交叉验证每个章节，可配置的服务商回退顺序（设置 → `harmony.translation.fallbackOrder`）
- **标准感知**：保留中国标准编号（3.1.2、GB/T 50378、CJJ 94、JGJ 16）
- **多格式**：接受 .md、.txt、.html、.pdf、.docx 文件
- **审计追踪**：争议账本记录每个有争议的术语选择
- **静态加密**：术语表和检查点以 AES-256-GCM 加密
- **批处理模式**：处理整个文件夹，每个文件有费用防护

### ⚠️ 重要 — 费用与限制

| 项目 | 详情 |
|:---|:---|
| **语言对** | 仅英文 ↔ 中文（EN↔ZH） |
| **AI 服务商** | DeepSeek、Qwen、Gemini、Moonshot/Kimi、Claude、Tencent — 可配置 |
| **费用** | 多模型翻译每份文件跨越 2–4 个服务商产生 API 费用。费用因文件大小、服务商、模型层级和当前服务商定价而显著不同。 |
| **防护** | 每个文件和每批次的尽力而为费用防护已到位，但服务商定价可能无预警变动——防护可能无法阻止所有费用。 |
| **准确性** | AI 生成的翻译——对于关键、法律或技术内容，务必由合格的人类翻译审核 |
| **隐私** | 内容仅传输至 AI 服务商进行处理；Harmony 或服务商不保留任何数据 |

### 🔄 服务商回退配置

当翻译流水线中的模型失败（超时、限流、内容过滤），Harmony 自动尝试您配置的回退顺序中的**下一个可用服务商**。默认顺序为：

```
DeepSeek → Alibaba/Qwen → Gemini → Moonshot/Kimi → Claude
```

> ⚠️ **Claude 是昂贵的回退选项。** 若您未配置 Anthropic API 密钥，Claude 会被静默跳过。若不想使用 Claude 作为回退，请从顺序中移除。通过以下方式配置：
>
> **设置 → `harmony.translation.fallbackOrder`**
>
> 没有 API 密钥的服务商会被静默跳过。您可以重新排序、添加或移除服务商。空列表完全禁用回填——失败的模型将仅显示错误。

### 快速开始

1. 打开 **Harmony 侧边栏** → **翻译工具**
2. 点击 **🚀 翻译文档** → 选择文件
3. 查看首次使用免责声明 → 确认

## Compose OCR

当您通过 Harmony Compose 面板附加截图时，Harmony 自动运行**免费本地 OCR**，然后决定是否调用付费视觉模型。若 OCR 提取到可用文本，则不进行视觉 API 调用——您获得即时、免费的文本提取。

**跨平台：** Tesseract.js 在所有平台（macOS、Linux、Windows）提供 OCR 回退支持。Windows 额外获得原生 OCR 层（Windows.Media.Ocr），实现更快的离线提取——就像将 Windows 截图工具内置于 Harmony 中。

**要求：**

- **所有平台：** Tesseract.js 已随扩展捆绑（无需额外设置）。
- **Windows（可选原生层）：** 安装 `pip install winocr Pillow` 以获得更快的原生 OCR。
- **macOS（可选原生层）：** 安装 `pip install pyobjc` 以使用 Apple VisionKit OCR。

无需 API 密钥。无需云端。无需费用。OCR 完全在您的机器上运行。若 OCR 未找到文本或结果模糊，Harmony 照常回退到视觉模型。

### 🛡️ 三重审核工作流

三重审核是一种结构化审查方法，使用多个服务商在代码变更发布前进行检查。它作为**DeepSwarm 流水线模板**可用——从侧边栏下拉菜单或命令面板选择 `🛡️ Triple-Check Audit`。

**工作原理（4 步）：**

1. **协作者扫描**——协调模型读取所有变更文件并生成审核计划，包含每个文件的具体检查
2. **直接检查**——多个模型直接读取每个文件，并对照实际源码验证每项发现
3. **Grep 验证**——设计并检查目标正则模式，捕获检查可能遗漏的内容
4. **最终裁决**——所有发现综合成表格，包含每个文件、每项检查和明确的 GO/NO-GO 状态

每轮交叉引用其他轮。模糊发现（截断、部分读取）被重新验证而非报告为问题。最终裁决表显示每个文件、每项检查和明确的 GO/NO-GO 状态。

此工作流对神经多样性开发者尤为有帮助：它外化审查清单，捕捉单轮审查遗漏的细节，并生成您可以日后重读的书面记录。

要运行三重审核：从 Harmony 侧边栏的 DeepSwarm 下拉菜单选择 **🛡️ Triple-Check Audit** 流水线，或从命令面板运行 `Harmony: Run DeepSwarm Pipeline` 并选择它。对于自动化预提交验证，配合 `npm run compile` 使用。

在 Steering → Context Persistence 部分启用 **🛡️ Triple-Check (auto-audit)** 复选框，可在每次聊天回合后自动审核代码变更。勾选后，轻量级单轮安全检查自动在已变更文件上运行——无需弹窗、无需下拉、无需额外输入。若发现问题，一键升级到完整的 4 步三重审核流水线。

### ⚠️ 费用意识

**DeepSwarm 倍增 API 调用。** 每步 3 个服务商的 4 步流水线产生 12+ 次 API 调用。下表显示相对费用，而非美元金额：

| 流水线规模 | 相对费用 |
|:---|:---|
| 1 步（单一服务商） | ●○○ 低 |
| 2 步 Thorough（2–3 服务商） | ●●○ 中等 |
| 4 步完整流水线 | ●●● 显著 |

实际费用取决于您配置的服务商、模型层级、提示词大小和缓存命中率。DeepSeek 调用受益于自动缓存定价检测（侧边栏中 ⚡缓存 指示器）。DeepSwarm 专为理解多服务商 API 定价的经验丰富用户设计——它不是"设置后不管"的自动化工具。若您不确定流水线做什么、调用哪些服务商或可能产生什么费用，**请勿运行。** 使用任何不完全理解的流水线前请寻求指导。完整条款见[法律 & 免责声明](#法律--免责声明)。

### 🛡️ 自愈引擎（Self-Healing Harness）

Harmony 的文件编辑工具使用 SHA256 验证的原子编辑，具备检查点和回滚功能。每次编辑前写入检查点。每次编辑后验证变更。若验证失败，引擎回滚到上一个已知良好状态。

- **SHA256 验证**——每次编辑经密码学验证
- **原子写入**——不可能出现部分写入；文件要么完全写入，要么不变
- **检查点**——编辑前快照支持即时回滚
- **冲突检测**——检测并拒绝过时/冲突编辑

设置见[可选：Python & 自愈引擎](#可选python--自愈引擎)。TypeScript 回退无需 Python 即可工作。

### 📝 指挥家日志（Conductor Journal）

Harmony 维护一份私密的加密反思日志——这是 AI 指挥家的认知卸载空间，用于在工作间隙记录会话经验、决策逻辑与设计考量。这份日志帮助 Harmony 在长时间会话中维持上下文连贯，记住所学内容而无需重新推导。

- **静态加密**——日志条目是私密的，存储在 `~/.harmony/conductor-journal/`
- **跨会话记忆**——经验在 VS Code 重启和新对话后仍然保留
- **自我改进**——检测到的模式和反模式被记录以供未来参考
- **零遥测**——日志永不离开本地

指挥家日志是专为 AI 设计的功能：它为 Harmony 自身的认知连续性而存在，而非供人类阅读。它通过保留原本会在对话轮次之间丢失的上下文，使长时间协作会话更加高效。
